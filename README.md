# Кварта: лендинг обжарки кофе

Сайт: https://kvarta-coffee-pi.vercel.app
Репозиторий: https://github.com/n-sokirko/kvarta_coffee

Русскоязычный лендинг вымышленной минской обжарки «Кварта» (тестовое задание). Next.js 15 (App Router), свой WebGL без библиотек, заявки принимает `POST /api/lead`.

## Что сделано

- **Страница.** Герой, история зерна (3D-переход зерно → кружка), блок про свежесть, ассортимент с ценами, подписка, история доставки (3D-переход пачка → фургон → дверь), доставка и самовывоз, «О нас», форма, контакты. Сцены нарисованы кодом, готовых моделей и картинок нет.
- **Форма.** Имя, телефон, что интересует (подписка, разовый заказ, вопрос), комментарий. Белорусский номер: маска при вводе, отдельное сообщение под каждую причину отказа (лишние знаки, не +375, неверное число цифр, неверный код оператора).
- **Повторная отправка.** Один номер не создаёт вторую заявку 10 минут, в том числе при двойном нажатии. Проверка и в браузере, и на сервере (подробности ниже).
- **Источник заявки.** UTM-метки, клик-идентификаторы рекламы (`gclid`, `fbclid`, `yclid`), реферер и страница входа сохраняются в браузере и уходят вместе с заявкой. Менеджер видит, из какой рекламы (`utm_campaign`), с какого объявления (`utm_content`) и с какой страницы пришёл человек.
- **Ошибка отправки видна.** Если сервер не ответил или не сохранил, над кнопкой появляется сообщение «Заявка не ушла» и что делать. Номер при этом освобождается, повторная попытка проходит.
- **Плюсы из ТЗ.** Дублирование заявки в Telegram (включается переменными окружения), превью ссылки (Open Graph), анимации.

## Бэкенд

`POST /api/lead` (`app/api/lead/route.ts`), тело JSON:

```json
{ "name": "Анна", "phone": "+375 (29) 123-45-67", "interest": "order", "comment": "", "source": { "utm_source": "instagram", "utm_campaign": "autumn", "utm_content": "banner-2", "landing": "/?utm_source=instagram" } }
```

| Ответ | Когда |
|---|---|
| `200 {"status":"ok"}` | заявка принята и сохранена |
| `200 {"status":"duplicate"}` | с этого номера заявка была меньше 10 минут назад, вторая не создаётся |
| `422 {"status":"invalid","field":"phone","reason":"country"}` | неверные данные; `reason`: `empty`, `format`, `country`, `length`, `code` |
| `500 {"status":"error"}` | не удалось сохранить; блокировка номера снята, можно повторить |

Номер приводится к `+375XXXXXXXXX`, поэтому `8 029…`, `+375 (29) …` и `375 29…` считаются одним номером. Сервер проверяет всё заново и не доверяет браузеру. Скрытое поле `company` служит ловушкой для ботов: если оно заполнено, отвечаем «принято» и ничего не сохраняем.

`GET /api/lead` с заголовком `x-admin-token` (переменная `ADMIN_TOKEN`) возвращает последние 100 заявок. Без токена отвечает 404.

### Где хранятся заявки и почему

Выбрано **Redis (Upstash)**, подключается через Vercel Marketplace.

- Файл и SQLite на Vercel не подходят: файловая система функций временная, заявки пропадут при следующем запуске.
- Повтор за 10 минут решается одной атомарной командой `SET dedupe:+375… NX EX 600`. Два одновременных запроса с одного номера физически не могут пройти оба, чего нельзя гарантировать при схеме «прочитать, потом записать».
- Заявки лежат списком `leads` (`LPUSH`), новые сверху. Для небольшого потока заявок этого хватает.

Локально без внешних сервисов работает запасной режим: заявки пишутся в `data/leads.jsonl`, занятые номера хранятся в памяти процесса. Выбор между режимами автоматический, по наличию переменных `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` (или `KV_REST_API_URL` и `KV_REST_API_TOKEN`).

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | хранилище заявок и блокировка повторов |
| `ADMIN_TOKEN` | доступ к `GET /api/lead` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | дублировать заявку в Telegram (необязательно) |
| `NEXT_PUBLIC_SITE_URL` | адрес сайта для превью ссылки |

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
npm run build && npm start
npm test             # логика телефона
BASE=http://localhost:3000 npm run test:api   # API, нужен запущенный сервер
```

Тест API проверяет: неверные номера и причины, повтор того же номера в другой записи, два одновременных запроса (ровно один создаёт заявку), ловушку для ботов, мусорное тело запроса.

## Производительность

Lighthouse, мобильный профиль (симуляция Moto G Power, медленный 4G), боевой адрес, три прогона после последней правки: **Performance 74–77, Accessibility 100, Best Practices 82, SEO 100**. FCP 3,0 с, LCP 4,6–4,9 с, TBT 0–70 мс, CLS 0,036.

Как достигнуто и чем это оплачено:

- Тяжёлая часть (WebGL) стартует **после первого действия человека**: прокрутки, касания или нажатия клавиши. До этого на первом экране стоит постер `hero-poster.webp`, показанный движком кадр. Без этого первый кадр на программном рендеринге Lighthouse занимал 6 секунд и Performance падал до 35–42. Цена: человек, который ничего не трогает, видит неподвижную картинку.
- Статические секции отдаются сервером готовым HTML, интерактивны только витрина и форма.
- Шрифты подключаются без блокировки первой отрисовки.

Что осталось: LCP 4,6–4,9 с (постер как фон), Best Practices 82 из-за стороннего скрипта антивируса в тестовом браузере и консольных предупреждений. Реальный телефон не проверялся, измерение только симулированное. После первой прокрутки сцены на слабом телефоне не мерились.

## Что делал человек, что ИИ

Работа шла в Claude Code, сессия экспортируется командой `/export`.

- **Человек.** Задал идею: рассказывать сначала про кофе, потом про доставку, с 3D-переходами «зерно → кружка» и «пачка → доставка»; потребовал настоящее объёмное зерно вместо нарисованного, потом реалистичнее налитие и доставку, зёрна оставил как есть; заметил нейрослоп в тексте и поставил задачу вывести правила и переписать; дал адрес репозитория и потребовал выложить фронтенд и бэкенд.
- **ИИ.** Весь код: WebGL-движок и сцены, страница, форма, бэкенд, тесты; текст страницы; разбор текстов других обжарок и правила; деплой.

### Где ИИ ошибся и как это заметили

- **Выдумал факты в тексте.** В первой версии текст про процесс (барабан, мешок, дата на каждой пачке, «курьер») придуман ИИ, в ТЗ такого нет. Заметили человек («нейрослоп») и независимый аудит строка за строкой; всё придуманное убрано.
- **Дефекты в 3D.** Дом получился размытым и ломаным, стекло окна мерцало, чайник обрезался на узком экране, фургон перекрывал крыльцо. Заметили по скриншотам, исправляли итерациями.
- **Маска телефона.** Маска «застревала» при стирании скобки или дефиса; исправлено, поведение закреплено тестами в `logic/`.
- **Чужой адрес.** При первом деплое имя `kvarta-coffee.vercel.app` оказалось занято чужим проектом с другой формой, на ней ответ `/api/lead` не совпал с нашим. Заметили по ответу, нашли настоящий адрес проекта и убрали чужой из метаданных.
- **Первая сборка Lighthouse.** Производительность 35 из-за WebGL на программном рендеринге; разобрано по трассировке, решение описано выше.

## Допущения (в ТЗ не сказано, решено самим)

- Телефона и соцсетей в ТЗ нет, на странице стоит `[ТЕЛЕФОН]`, его нужно заменить.
- Доставка меньше 50 BYN платная, цену называют по телефону; адрес уточняется при звонке (в форме поля адреса нет).
- «На 1–3 день после обжарки» понято как «через 1–3 дня»; откуда берутся второй и третий день при доставке только по пятницам, неясно.
- Срок перезвона не указан и на странице не обещается.
- В названии кнопок и тексте нет «менеджера»: пишем «мы перезвоним».

## Что не успели или сделали бы иначе

- Перенести стартовый постер на настоящий снимок первого кадра для каждой ширины экрана.
- Проверить сцены на реальных телефонах и сократить размер шейдеров.
- Панель для менеджера (сейчас список заявок только через `GET /api/lead` или консоль Redis).
- Ограничение частоты запросов по IP.
- Сервис писем или мессенджера для ответа клиенту.
